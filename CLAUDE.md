# MedHub — инструкции для Claude

Платформа для студентов-медиков: ванильный JS SPA, без сборщика. RU / UZ / EN, три темы.
Прод: https://medhub-g6dl.onrender.com — **статический** сайт на Render (`render.yaml` → `runtime: static`).

## Главное правило: изменения сразу на сайт

Владелец хочет, чтобы каждое готовое изменение сразу попадало на сайт:

1. Работай в ветке `claude/<тема>` от свежего `origin/main`.
2. Проверь локально (см. «Проверка» ниже), закоммить.
3. Push ветки → Pull Request в `main` → **сразу смержи** (REST: `gh api -X PUT repos/shoxshavkatov-sudo/medhub/pulls/<n>/merge -f merge_method=merge`; GraphQL `gh pr create` в облачных сессиях недоступен — PR создавай через `gh api repos/.../pulls`).
4. Render сам пересобирает сайт из `main` (~1 мин). Проверь, что на проде новая сборка: `curl -s https://medhub-g6dl.onrender.com/ | grep -o 'r/[0-9]*/js/app.js'` — номер должен смениться.
5. Сообщи владельцу, что изменение на сайте.

Не мержь то, что не проверено. Если что-то сломано — сначала почини, потом мерж.

## Кэш: почему build.sh, а не только ?v=

CDN Render (Cloudflare) кэширует файлы до часа и **не различает `?v=` в адресе** — после деплоя
изменённый `app.js` мог отдаваться старым. Поэтому сборка идёт через `build.sh` (`buildCommand` в `render.yaml`):
каждый деплой кладёт `js/` и `css/` в новую папку `r/<время сборки>/`, и `index.html` ссылается на неё.
`news.js` и `icd-info.js` грузятся из той же папки (`ASSET_BASE` в начале `js/app.js`).

- Ничего специально делать не нужно: любой деплой получает новые адреса.
- `?v=…` в `index.html` можно оставлять — не мешает, помогает браузерному кэшу при локальном запуске.
- Не меняй `buildCommand` и не удаляй `build.sh`. Новую папку с ресурсами, которые часто меняются, добавь в `build.sh`.
- Картинки (`img/`) кэшируются на 7 дней: при замене картинки давай файлу **новое имя**.

## Структура

| Файл | Что внутри |
|---|---|
| `index.html` | каркас, шапка, подключение скриптов (порядок важен) |
| `js/app.js` | вся логика: состояние `S` (localStorage `medhub`), `ROUTES.<имя>` + `.after`, `go(route, arg)`, док `DOCK` |
| `js/i18n.js` | строки RU / UZ / EN (`t(key)`, нет ключа → берётся `ru`). Новый ключ добавляй **во все три языка** |
| `js/data.js`, `js/data2.js` | встроенные справочники: `ICD10`, `DRUGS`, `LABS`, `PROTOCOLS`, `CALCS`, `ECGS`, `ATLAS`… |
| `js/icd-info.js` | краткая справка по кодам МКБ: `ICD_INFO["I21"] = "Суть|Клиника|Диагностика|Лечение"` (пустое поле пропускается) |
| `js/icd-uz.js` | справка МКБ на узбекском: `ICD_UZ["I21"] = "Nomi|Mohiyati|Klinika|Tashxis|Davolash"`; грузится только при языке uz, пустое поле → русский текст |
| `js/ref-extra.js` | механизм и побочные для 78 препаратов `data.js`, признаки и «что дальше» для 12 протоколов |
| `js/drugs-more.js` | ещё 131 препарат `{n, lat, cl, g, mech, ind, dose, contr, se, inter, preg, uz:{…}}` + `DRUG_UZ` (перевод препаратов `data.js`); грузится по требованию (`RefData`) |
| `js/protocols-more.js` | ещё 69 протоколов + `PROTOCOL_UZ`; грузится по требованию (`RefData`) |
| `js/tests-more.js` | клинические тестовые вопросы, RU + UZ в каждом: `sub('Предмет', 'Fan')`, `q(верный 0–3, вопрос, [4 варианта], пояснение, savol, [4 variant], izoh)`; грузится при входе в «Тесты» (`TestsMore`) |
| `js/cases-more.js` | ещё клинические случаи «Случайного пациента», RU + UZ в каждом: `k(направление, {случай как в CASES}, {uz})`; `CASE_CAT` — направления случаев из `data2.js`; грузится при входе в раздел (`CasesMore`) |
| `js/uz-data.js` | узбекский перевод содержимого разделов (предметы, навыки, анализы, калькуляторы, симуляторы, тесты, пациенты, карточки): словарь `UZT["русская строка"] = "o'zbekcha"`; грузится только при uz (`UzData`), подставляется через `tz()` в `js/app.js`. Меняешь русский текст в `data.js`/`data2.js` — поправь ключ здесь |
| `js/glossary.js` | глоссарий: `e(категория, 'ключи RU', 'ключи UZ', 'определение RU', 'определение UZ')`; в справке термины подчёркиваются (`Gloss` в `js/app.js`), раздел «Глоссарий» |
| `js/news.js` | новости: `addNews({date, title, text, image?, link?, pinned?})`; генератор кода — сайт с `?editor` |
| `js/liquid-dock.js`, `css/liquid-dock.css` | нижняя панель «Liquid Glass» |
| `css/style.css` | все остальные стили; цвета — переменные на `:root` и `[data-theme="dark"|"night"]` |
| `server.js` | Node-версия (группы между устройствами). **На проде не используется** — там статика |

Справка (`ROUTES.icd / drugs / protocols`) построена на общем модуле `Ref` в `js/app.js`:
свёрнутые группы по умолчанию, при поиске — только совпадения с подсветкой.

## Лицензия Liquid Glass

Нижняя панель основана на наборе «Liquid Glass для Telegram Mini Apps» © Volodymyr (@vovnx).
Используется с разрешения автора. **Не удаляй упоминание автора** в `js/liquid-dock.js` и `css/liquid-dock.css`.

## Проверка

Собери копию как Render и открой в Playwright (Chromium уже установлен):

```bash
mkdir -p /tmp/site && cp -R index.html js css img vendor models build.sh /tmp/site/ && cd /tmp/site && bash build.sh && cd dist && python3 -m http.server 8765
```

Минимум: стартовая страница без `pageerror`, изменённый раздел на 1280px и 360–375px, светлая и тёмная тема,
нет горизонтальной прокрутки. При первом заходе открывается окно регистрации — закрой его `Escape`.
404 на `/api/health` — норма для статического режима.

## Стиль

- Интерфейс и комментарии — на русском; тексты UI — через `t()`, не хардкодом.
- Иконки — SVG через `ic(name)` (`ICONS` в `app.js`), не эмодзи.
- Медицинские тексты — учебные, кратко и по делу; на сайте есть дисклеймер «не для клинических решений».
